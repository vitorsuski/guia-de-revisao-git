# GitHub Flow

## Os seis passos do GitHub Flow

1. Criar uma branch a partir da main.
2. Fazer as alterações necessárias nos arquivos.
3. Registrar as alterações utilizando commits.
4. Abrir um Pull Request para solicitar a revisão.
5. Revisar o trabalho, pedir ajustes se necessário e aprovar.
6. Fazer o merge para juntar as alterações à main.

## Por que não editamos diretamente na main?

Não editamos diretamente na main porque ela é a branch principal do projeto. Trabalhar em branches separadas permite revisar as alterações, corrigir erros e evitar problemas antes de atualizar a versão principal.

## O que significam o vermelho e o verde no diff?

O vermelho representa as linhas removidas ou substituídas e o verde representa as linhas novas adicionadas ao arquivo.
